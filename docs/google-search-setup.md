# Google Search setup checklist

Manual steps that need access to the Google Search Console account for
`blog.ratneshmaurya.com`. Nothing here has been done or verified from the codebase.

Host and origin live in `src/lib/site.ts` (`SITE_HOST`, `SITE_URL`). If the domain
changes, the Preferred Source link, canonicals, sitemap and JSON-LD all follow it.

## 1. Verify the property

1. Open [Search Console](https://search.google.com/search-console) and add a property.
2. Prefer a **Domain** property for `ratneshmaurya.com` (covers the blog subdomain and the
   portfolio) with the DNS TXT record. A **URL-prefix** property for
   `https://blog.ratneshmaurya.com/` also works (HTML tag or DNS).
3. Confirm the property shows "Ownership verified".

## 2. Search generative AI inclusion

Google's Preferred Sources doc says the "preferred" badge in AI Mode and AI Overviews needs
the site to be included in Search generative AI features in Search Console.

1. In Search Console, look for the generative AI / AI features setting for the property
   (the exact location may change; follow the link in the Preferred Sources doc).
2. If the setting is not visible for the property, record that here instead of assuming
   it is on.

## 3. Submit the sitemap

1. Search Console, **Sitemaps**, enter `sitemap.xml`, **Submit**.
2. Expect `https://blog.ratneshmaurya.com/sitemap.xml` (generated by `src/app/sitemap.ts`).
3. Check that the status is "Success" and the discovered URL count is plausible.

## 4. Inspect article URLs

For a few recent articles (`/blog/<slug>/`):

1. Paste the URL into the **URL inspection** bar.
2. Check "URL is on Google". If not, use **Request indexing** once, not repeatedly.
3. Use **Test live URL**, then **View tested page**, and confirm rendered HTML, screenshot
   and resources.

## 5. Check canonical URLs

In URL inspection, compare **User-declared canonical** with **Google-selected canonical**.
They should both be the trailing-slash URL `https://blog.ratneshmaurya.com/blog/<slug>/`.
A mismatch means Google sees duplicates (for example the old `blog.ratnesh-maurya.com` host).

## 6. Test structured data

1. [Rich Results Test](https://search.google.com/test/rich-results) with an article URL.
2. [Schema Markup Validator](https://validator.schema.org/) for the full graph.
3. Expect on an article page: `BlogPosting`/`Article`, `BreadcrumbList`, plus the site-wide
   `Person`, `Organization`, `WebSite` graph and `ProfilePage`.
4. Warnings about optional fields are not errors. Structured data helps Google understand a
   page; it does not guarantee rich results or citations.

## 7. Monitor indexing and performance

- **Pages** report: indexed vs not indexed, and reasons.
- **Performance** report: queries, pages, countries; filter by `/blog/`.
- **Sitemaps** and **Core Web Vitals** reports: check weekly after releases.

## 8. Preferred Sources eligibility

Doc: <https://developers.google.com/search/docs/appearance/preferred-sources>

1. Open <https://www.google.com/preferences/source?q=blog.ratneshmaurya.com>, or search the
   source preferences tool for the site name, and see whether the site is listed.
2. Only domain- or subdomain-level sites are eligible; a sub-path such as `/blog` is not.
3. If the site is not listed yet, nothing on the site can force it. Keep publishing and
   re-check later.
4. After it is listed, click the button on the live site (footer, home page, article pages)
   and confirm the Google dialog opens. The component falls back to a plain link to the
   source preferences page if Google's script does not render the button.

Using the button is optional. Google does not say it changes rankings.

## How the button is built

`src/components/PreferredSourceButton.tsx`:

- Loads `https://news.google.com/swg/js/v1/publisher.js` once with `next/script`
  (`id="google-preferred-source"`, `lazyOnload`), however many buttons are on the page.
- Renders `<div google-add-preferred-source-btn data-theme="light|dark">`, the documented
  standard implementation.
- If the button has not rendered 1.5s after the script is ready (or the script fails),
  shows a link to the source preferences page. A `<noscript>` link covers no-JS visitors.
- publisher.js scans the page when it loads, so a button that appears later through a
  client-side navigation may not be picked up; the fallback link covers that case.
